## 0. 소실과 중복은 같은 뿌리다

두 증상을 따로 겪었는데 원인이 하나였다 — **열거인데 스칼라로 다뤘다**.

| 증상 | 어떻게 났나 |
|---|---|
| **소실** | `--done-criteria` 를 5번 줬는데 `argparse` 가 마지막 하나만 남겼다. diff 를 보고서야 알았다 |
| **중복** | 그걸 피하려 값 안에 개행 + `- 완료 기준: ` 접두사를 넣었더니, `_set_inline_field` 가 **첫 줄만** 교체해 2번째 이후가 남았다. update 두 번에 두 벌이 됐다 |

우회책이 두 번째 결함을 만들었다. 스칼라 API 를 목록처럼 쓰려면 값 안에 구조를 넣는
수밖에 없고, 그 구조는 **읽는 쪽이 모른다**.

## 1. 처방 — `action="append"` + 묶음 단위 교체

- 열거형 네 필드(`완료 기준` / `작업 결과` / `남은 리스크` / `후속 작업`)를
  `action="append"` 로. 값 하나당 한 줄로 렌더한다.
- `_set_list_field` 신설 — **연속한** `- <label>:` 줄을 한 묶음으로 보고 통째로
  교체한다. 중간에 다른 라벨이 끼면 거기서 끝나므로 **다른 절의 같은 라벨은 안
  건드린다** (case 8 이 그 경계를 잰다).
- update 는 `list_updates` 로 흘려 스칼라 경로와 섞이지 않게 했다.

멱등이 계약이다 — 같은 값으로 두 번 돌리면 파일이 같다 (case 5). `진행 현황` 은
타임스탬프를 담아 매번 달라지므로 그 줄만 빼고 비교한다.

## 2. 되주입이 원래 증상을 그대로 재현했다

| 심은 결함 | 나온 실패 |
|---|---|
| `action="append"` 제거 | case 1 `['- 완료 기준: C']` — **마지막 하나만 남는 소실 그대로** |
| 묶음 교체 → 첫 줄만 | case 4 `['X','Y','B','C']` · case 5 · case 7 — **중복 누적 그대로** |

검사가 "고쳤다" 가 아니라 **"그 결함이면 실패한다"** 를 보인다.

## 3. 자기 적용은 흔적을 본다

case 9 는 저장소의 task 파일에 **같은 줄이 중복 누적**돼 있는지 본다. 옛 우회책이
남긴 흔적이 있으면 그것부터 드러난다 (현재 0건).

## 4. 남은 것 — 3단계

2단계는 **쓰는 쪽**을 목록으로 만들었다. 남은 것은 본문 라벨의 영어화인데, 그
선행 조건이 이제 갖춰졌다:

- `status` 는 1단계에서 frontmatter 가 정본이 됐다
- 열거형 필드는 2단계에서 **인자 → 렌더 → 교체**가 라벨 문자열 하나에만 의존하게
  모였다 (`_set_list_field(lines, label, values)`)

즉 라벨을 바꾸려면 이제 **정본 상수 한 곳**을 옮기면 되는 모양에 가까워졌다. 다만
아직 라벨 리터럴이 `backlog_update` / `read_only_bundle` / `workflow_writes` 에
흩어져 있어, 3단계의 첫 일은 **그 리터럴을 한 자리로 모으는 것**이다.
