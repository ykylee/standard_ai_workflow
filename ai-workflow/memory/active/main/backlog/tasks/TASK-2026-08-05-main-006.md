## ✅ Outcome

- 작업 결과: 먼저 **조사 결과가 예상과 달랐다.** "우리 mcp 를 2.0.0 에 맞게 다 고쳐야겠다" 로 시작했는데, 전수 조사 결과 고칠 production 이 **0건** 이었다. `read_only_mcp_sdk` 는 `CallToolResult` 를 **생성할 때** camelCase kwarg 를 쓰고 2.0.0 이 alias(`populate_by_name` + camel alias generator)로 받는다 — 이미 정합이고 매트릭스가 계속 그것을 증명해 왔다. `protocolVersion` / `listChanged` 문자열은 MCP **프로토콜 자체의 wire 필드명** 이라 SDK 파이썬 필드명과 무관하다. 함정은 **속성 읽기**(`result.isError`)뿐이고 production 에는 0건, 내가 쓴 새 검사에만 있었다.
  더 뼈아픈 것은 이 저장소가 **그 함정을 이미 알고 있었다** 는 점이다 — `read_only_mcp_sdk` 주석과 `check_mcp_lowlevel_sdk_compat` 계약 6번이 정확히 그것을 적어 두고 있다. 그런데 그 검사는 production 패턴만 보고, 새 파일에 `.isError` 를 적는 것은 막지 못했다. 로컬 venv 가 1.27.0 하나라 통과했고 매트릭스가 아니었으면 그대로 들어갔다.
  그래서 고친 것은 코드가 아니라 **구조**다: `sdk_matrix --run-local` 로 `PINNED_VERSIONS` 3버전을 로컬 venv 에서 그대로 밟는다. 버전 목록은 CI yml 과 같은 정본에서 읽으므로 사본이 없다. venv 는 `.venv-sdk-matrix/` 에 캐시.
  그리고 발견 가능성 — `CLAUDE.md` 의 "프로젝트 실행 기본값" 5항목이 **전부 TODO placeholder** 였다. 실행 기본값을 배포하는 저장소가 자기 것은 한 번도 채우지 않았다. 실제 명령으로 채우고, SDK 매트릭스 절을 추가하고, placeholder 로 되돌아가는 것을 case 2d 로 막았다.
