## 🛠️ Implementation / Content

- Progress: 완료.
- 설계 결정:
  - **활성 브랜치 = 진행 중 작업 목록**. 브랜치 선점이 곧 배타 획득(§5D.1)이므로 원격
    저장소 자체가 현황판이다 — 별도 registry 불필요.
  - **fetch 가 기본값**, 생략하려면 `--no-fetch` 를 명시해야 한다. 낡은 ref 로 stale 을
    판정하면 *살아있는 작업을 지우자고 제안*하게 되기 때문 (§5D.4a 실측).
  - **아무것도 삭제하지 않는다** — stale 은 판정이 아니라 질문이다. 사용자가 판단할
    근거(owner / idle / 마지막 커밋 / 작업 축)를 함께 싣는다 (표준 §10.4).
  - 지표는 `%ct`(commit date). `%at` 는 rebase 시 원본 시각을 유지해 활동성 지표로 부적합.
