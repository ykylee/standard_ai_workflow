## 🛠️ Implementation / Content

- 진행 현황: 완료.
- 설계 결정:
  - **시그니처**: `_branch_state_paths(*roots: Path) -> list[Path]`. 단일 호출
    (`_branch_state_paths(root)`) 은 그대로 동작 *+* 가변 인자. 후방 호환.
  - **sort/dedupe**: 결과는 `sorted({p.resolve() for ...}).` 동일 내용은 한 번.
  - **자동 worktree**: `collect_recent_releases` 내부에서 self root 의
    `git worktree list --porcelain` 1회 호출, main worktree 외 N 개를 `extra_roots`
    로 합류. 파이프 실패 / `git` 부재 / 결과 0개 시 *조용히* 자기 root 만 사용.
  - **env**: `WORKFLOW_EXTRA_ROOTS` (`os.pathsep` 구분) 도 자동 합류. 둘 다 없으면
    단일 root 와 결과 동일.
  - **파생 뷰 원칙 준수**: 새 파일을 만들지 않는다. §6 의 *집계는 파일이 아니라 뷰* 와
    정합 (§7.3 의 §6 ref).
  - **회귀`: `tests/check_dashboard_multi_root_aggregator.py` 5~6 assertions:
    (a) 단일 root = 구 동작과 동일. (b) 추가 root 의 state.json 항목이 timeline 에
    합류. (c) dedupe. (d) `rglob` skip (디렉터리, json 아님). (e) `git` 부재/실패
    시 추가 root 0개로 fallback. (f) `WORKFLOW_EXTRA_ROOTS` env 1개로 합류.

- 비범위:
  - workspace registry 도입 (다음 사이클).
  - cross-host (여러 서버) — registry 와 동시.
  - CLI flag 추가 — env 1개 + 자동 기동만.
