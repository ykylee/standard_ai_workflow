- 작업 내용: 같은 호스트 안의 두 자료원 (`~/.cache/workflow_kit/registry.json` +
  `~/.minimax/mcp/mcp.json`) 이 서로 모르는 상태로 살아있다. registry 가 알려주는
  workspace 가 mavis 글로벌에 자동 attach 되지 않고, mavis 글로벌의 5종 builtin +
  `standardAiWorkflowReadOnly` 외의 사용자 alias 들이 dashboard 가 *진행 중* 으로
  인식되지 않는다. registry ↔ mavis 글로벌 양방향 동기:
  - **import_mavis_aliases**: mavis 글로벌의 *workflow_kit 외* alias 들을 registry
    entries 로 환원. `path=__mavis__/<alias>`, `branch=alias`, `harness="mavis-bridge"`,
    `endpoint="<command 또는 url>"`. 등록은 *현재 호스트의 host_id* 로. 이미 registry
    에 동일 path 있으면 skip (idempotent).
  - **export_to_mavis**: registry 의 entries 중 `path` 가 *현재 저장소 root* 와
    일치하는 것들을 mavis 글로벌의 `mcpServers` 아래 `mavis:<branch>` alias 로
    emit. 단, *default 는 user-confirm 모드* (export --apply 명시 시에만 실제
    변경). 이미 있으면 skip (force 옵션만 overwrite).

  통합 CLI: `sync-mavis` 가 두 방향을 *한 번에* 수행. *import 만* / *export 만*
  도 가능.

- 완료 기준: (1) import 1+ alias → registry 1+ entry (idempotent, 합리적 환원).
  (2) export 1+ entry → mavis 글로벌 mcpServers 에 1+ alias (default confirm, --apply
  시 atomic). (3) sync: import + export 양쪽 PASS. (4) builtin 5종 + 우리 alias
  보호. (5) 회귀 5+ assertions. (6) 전체 회귀 13+ green.

## 🛠️ Implementation / Content

- 진행 현황: 완료.
- 설계 결정:
  - **alias ↔ entry 환원 규칙**:
    - mavis 글로벌에서 가져온 alias 는 `path="__mavis__/"` *+* alias 로 canonical
      화. 실제 파일 시스템 경로가 아니라는 사실을 *명시적 prefix* 로 표시.
    - `branch` = alias (mavis 의 mcpServers key 자체).
    - `harness` = `"mavis-bridge"` (관용치).
    - `endpoint` = 그 alias 의 `command` 또는 `url` (mavis 글로벌에서 의미 있는 식별자).
  - **export 의 user-confirm default**: `export_to_mavis` 가 *default* 로는
    *dry-run* (변경 없이 무엇이 추가될지 보고). `--apply` 명시 시에만 atomic write.
    export 자체가 *부수적* 동작 (in-flight 가시성) 이라 §5A.3 정합.
  - **import 의 user-confirm default**: `import_mavis_aliases` 도 *default* dry-run.
    registry 는 *사용자 모르게* 변하지 않아야 한다 (§7.1 *소비자가 생길 때* 원칙).
  - **builtin 5종 보존**: export 시 `matrix` / `playwright` / `cu` / `trash` / `github`
    + `standardAiWorkflowReadOnly` 는 *절대 덮어쓰지 않음* — registry entries 와
    매치되는 alias 가 있어도 builtin alias 보호.
  - **conflict skip**: import 시 alias 가 이미 우리 alias 라면 (표준 alias 와 같으면)
    skip. export 시 mavis 글로벌에 *그 branch 의 우리 registry entry 와 의미가 같은*
    alias 가 이미 있으면 skip.
  - **단방향 ↔ 양방향**: `--import-mavis` / `--export-mavis` 가 단방향, `--sync-mavis`
    가 양쪽. 양쪽이 따로 있는 이유는 호출자 의도 명시 (CI 자동화 vs 운영 정리).

- 비범위:
  - cross-host sync (registry 끼리; cross-host 가설, 다음 사이클).
  - mavis alias 의 env 자동 합성 (export 시 registry entry 의 `STANDARD_AI_WORKFLOW_ROOT` /
    `PYTHONPATH` 가 있으면 합쳐 merge — 이건 다음 task 후속).
