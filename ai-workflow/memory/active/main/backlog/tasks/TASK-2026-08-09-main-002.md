## 🛠️ Implementation / Content

**설계 결정 — 새 dispatcher 를 만들지 않았다.** TASK-020 노트는 `tools/cli/dispatcher.py`
신설을 적어 뒀지만, 확인해 보니 `workflow_kit_cli.py` 가 이미 38 subcommand dispatcher
였다. 그대로 따랐으면 진입점이 둘로 갈리고 `--help` 도 둘로 갈린다. 사용자 확인 후
**기존 registry 확장** 으로 갔다.

**정공법도 이미 있었다.** `score-wiki-trend` (v0.7.56+) / `consumer-metrics` (v0.7.59+)
wrapper 가 쓰던 *sys.argv 치환 + SystemExit → rc* 패턴을 29개로 일반화한 것이
`tool_dispatch.run_tool()` 이다.

- `TOOL_MODULES` (29개) 가 정본. `[project.scripts]` 와의 일치를 smoke 가 강제 —
  A안/B안 두 표면이 같은 것을 가리킨다는 게 유일한 약속이라, 한쪽만 느는 사고를 막는다.
- `main()` 시그니처가 13 : 16 으로 갈려 있다 (`main(argv)` vs `main()`).
  29개 파일을 통일하는 대신 `inspect.signature` 로 읽어서 맞춘다 — 변경면이 훨씬 작다.
- lazy 등록 (`make_tool_runner` 클로저) — 등록 시점에 29개를 import 하면 `wk --help`
  한 번이 모든 tool 의 import 비용을 문다.
- 기존 wrapper 2건(`score-wiki-trend` / `consumer-metrics`)은 **덮지 않는다**:
  그쪽 docstring 에 arg surface 가 적혀 있고 호출 경로가 v0.7.56 부터의 약속이다.
- completion 은 `wk --list-commands` 를 먹는다 — 이름을 하드코딩하면 tool 이 늘 때
  두 곳을 고쳐야 하고, 한쪽을 잊으면 completion 이 거짓말을 한다.
