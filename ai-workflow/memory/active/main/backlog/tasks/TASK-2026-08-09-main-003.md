## 🛠️ Implementation / Content

**구멍이 두 개였다.** 서빙하는 쪽이 없어 `http://` endpoint 는 문서상의 형식일
뿐이었고 — 더 조용하게는 — `add_known_host()` API 가 TASK-015 부터 있었지만
**부르는 CLI 가 없었다.** 서버를 띄워도 상대가 등록을 못 하니 federation 은 어느
쪽으로도 돌지 않았다. 둘 다 이번에 메웠다.

안전 기본값과 근거:

- bind `127.0.0.1` 기본. registry 에 워크스페이스 절대 경로 + 브랜치가 들어 있어,
  파일만 0o600 이고 HTTP 가 0.0.0.0 이면 보호가 무의미하다. 외부 bind 는 경고하되
  거부하지 않는다 (LAN federation 은 정당하다).
- `SimpleHTTPRequestHandler` 미사용 — 디렉터리 노출 + traversal 표면이 딸려 온다.
  아는 경로는 `/registry.json` + `/healthz` 둘뿐.
- read-only (쓰기 405). 원격이 남의 registry 를 고칠 수 있으면 federation 모델이 무너진다.
- 토큰은 **환경변수 이름** 으로 (`--token-env`). `--token=SECRET` 은 ps / history 에 남는다.
  `KnownHost.token_env` 도 이름만 저장 (additive, missing → "" 하위호환).
- registry 부재 → 빈 registry (404 아님). 404 면 상대가 *호스트가 죽었다* 고 오해한다.
- `Cache-Control: no-store` — 오래된 뷰는 §0.8 #2 confidence 판정을 거짓말로 만든다.
