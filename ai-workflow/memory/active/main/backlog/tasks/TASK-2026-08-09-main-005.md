## 🛠️ Implementation / Content

v1 (TASK-018) 은 TASK-ID **집합** 만 비교했다. "TASK-001 을 계획했고 TASK-001 을
했다" 면 그 사이에서 내용이 통째로 바뀌었어도 **언제나 clean** 이었다.

v2 는 같은 ID 의 **제목** 을 `difflib` 로 비교해 후보를 고르고, 판정은 LLM prompt 로
넘긴다. LLM API 를 직접 부르지 않는다 — `purpose_refresh` 와 같은 advisory 모델이고,
제목이 바뀐 이유를 아는 건 결국 사람이다.

- 문자 기반 유사도를 쓴다. 제목이 한국어 + 영어 식별자 혼합이라 공백 토큰화가 안 맞는다.
- `detect_scope_drift()` 에 `title_drift` **additive** — v1 필드는 그대로다.

**실측으로 걸린 함정**: 처음 구현은 ID *뒤* 만 제목으로 봤는데, handoff §5 는
`- **항목명** — ✅ 닫힘 (TASK-xxx, …)` 형식이라 **ID 가 뒤에** 온다. 그 결과
`", 본 세션). 4-level enum + Panel 5"` 같은 설명 꼬리를 집었다. 지금은 ID 앞에
텍스트가 있으면 그쪽을 쓴다. 이 케이스를 회귀 검사에 넣었다 (3b).
