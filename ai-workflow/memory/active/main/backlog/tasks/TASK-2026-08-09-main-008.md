### 한 번 red 였다가 재실행에서 통과한 것 1건

`check_release_pipeline_lib::test_cmd_dist_1_command_build_check_testpypi_v0_8_15`
가 첫 실행에서 `expected skipped=True, got mode=apply` 로 실패했고 재실행에서 9/9
PASS 했다. 원인은 **버전 bump 직후 일회성**이다: 이 테스트는 `skip_existing=True`
로 부르면서 *현재 버전의 dist artifact 가 이미 있음* 을 전제하는데, 1.1.2 로 막
올린 직후라 `dist/` 에는 1.1.1 것만 있었다. 첫 실행이 1.1.2 를 build 하면서
skip 조건을 못 채웠고, 그 build 덕에 두 번째부터 통과한다.

`_ensure_dist_built()` 가 그 전제를 만들어 주도록 돼 있지만 **현재 버전 기준으로는
보장하지 못한다** — fresh clone 과 버전 bump 직후에 같은 모양으로 red 가 난다.
후속 후보.

## 발견한 도구 결함 (후속)

`release-bump --apply` 의 post-step `sync_release_hash` 가 실패한다:

```
fatal: 'workflow-source/pyproject.toml' 경로명세가 어떤 파일과도 일치하지 않습니다
warning: 'workflow-source/workflow-source/' 디렉터리를 열 수 없습니다
```

`git add` 에 경로가 **중복 prefix** 로 들어간다 — cwd 를 `workflow-source/` 로 잡으면서
경로에도 `workflow-source/` 를 붙인다. 버전 파일 2개(`pyproject.toml` /
`__init__.py`)는 정상 갱신되고 잘못된 `git commit --amend` 는 실행되지 않으므로
릴리스 자체는 막히지 않는다. 다만 자동화가 반쪽이라 hash 동기와 amend 를 사람이
해야 한다. **후속 TASK 로 분리** — 릴리스 도중에 릴리스 도구를 고치지 않는다.

같은 호출에서 **더러운 트리를 정확히 거부한 것은 좋았다**: "post-step
`git commit --amend` 가 미커밋 작업을 release commit 에 흡수합니다" 라며 멈췄다.
