## 🛠️ Implementation / Content

**(1) `git add` 경로 중복** — `release_pipeline.REPO_ROOT` 는 이름과 달리
`workflow-source/` 다 (`parents[1]`). `git status --porcelain` 은 **저장소 루트 기준**
경로를 내놓으므로, 그걸 `cwd=REPO_ROOT` 에서 `git add` 에 넘기면
`workflow-source/workflow-source/pyproject.toml` 이 된다.

`_git_toplevel()` (= `git rev-parse --show-toplevel`, 실패 시 `REPO_ROOT.parent`) 을
신설하고 **git 경로를 다루는 세 자리**(`_git_dirty_paths` 의 status / `git add` /
`git commit --amend`)가 그것을 cwd 로 쓰게 했다. `REPO_ROOT` 상수에는 이름이 거짓인
이유와 함정을 주석으로 남겼다 — 다른 용도(`pyproject.toml` / `releases/` 열기)로는
그 값이 맞아서 이름만 고치면 광범위한 변경이 된다.

**(2) `cmd_verify` 의 `AttributeError: 'dry_run'`** — `_make_args()` 가 `dry_run` 을
안 채웠는데 `release_pipeline.cmd_verify` 는 `args.dry_run` 을 읽는다.
defaults 에 `dry_run: True` 를 **안전측** 으로 넣고, 실제 조회가 목적인 `cmd_verify`
wrapper 는 `dry_run=False` 를 명시했다 (True 면 gh 명령 문자열만 돌려주고 끝난다).

**(3) 회귀 검사 신설** — `check_release_wrapper_args.py` (8 case). 이번 교훈이
*"릴리스 도구는 릴리스 때만 실행되므로 평소 검사에 안 걸린다"* 였으므로, 릴리스를
돌리지 않고도 잡히게 만든다:

- `_make_args` defaults ↔ 각 `cmd_*` 의 `args.X` 참조를 **AST 로 대조**
- `_git_toplevel()` ≠ `REPO_ROOT` 확인
- dirty path 를 두 cwd 에서 각각 `git add --dry-run` — toplevel 은 성공,
  `workflow-source/` 는 **실패해야** 통과 (버그 자체를 회귀로 고정)
- read-only wrapper 4종 실호출로 AttributeError 부재 확인

**후속으로 함께 닫은 것 — dist skip 전제 (버전 bump 직후 일회성 red)**

`check_release_pipeline_lib::test_cmd_dist_1_command_build_check_testpypi_v0_8_15`
가 v1.1.2 발행 직후 첫 실행에서만 red 였다. 원인은 **두 판정 기준이 달랐던 것**:

| 자리 | 기준 |
| --- | --- |
| `cmd_dist(skip_existing=True)` | `find_dist_files(current_version)` — **현재 버전** |
| test 의 `_ensure_dist_built()` | `dist/*.whl` 이 **하나라도** 있으면 통과 |

버전을 올리면 `dist/` 에는 직전 버전 whl 만 있다 → 헬퍼는 "있다"며 build 를
건너뛰는데 `cmd_dist` 는 현재 버전을 못 찾아 build 를 수행 → `skipped=False` 로
단언 실패. 그 build 가 새 버전 artifact 를 남기므로 **두 번째부터 통과**한다.

헬퍼가 `cmd_dist` 와 **같은 함수**(`find_dist_files` / `read_version`)로 판정하게
고쳤다 — 기준을 따로 적으면 또 갈라진다.

이 헬퍼는 v1.0.1 에서 *fresh clone 상태 의존* 을 고치려고 도입된 것인데, 같은
부류의 상태 의존이 하나 남아 있었다. **"가정하지 말고 전제를 만든다" 는 맞았지만,
만든 전제가 소비자의 기준과 달랐다.**

**실증**: 현재 버전 dist 를 치워 bump 직후를 재현하니 수정 전 **8/9**,
수정 후 **9/9**.

**검사가 만든 오탐 1건 (고침)**

첫 버전은 `cmd_gen_schema` 의 `args.check` 를 "덮이지 않은 참조"로 보고했다.
그 함수는 **wrapper 없이 argparse 로만** 불려 `_make_args` 를 거치지 않는다 —
없는 결함이었다. 대상을 `release_pipeline_lib` 가 `mod.cmd_X(...)` 로 부르는 것만
으로 좁혔다. **검사의 범위가 실제 호출 경로보다 넓으면 없는 결함을 만든다.**
