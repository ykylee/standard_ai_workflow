**error_code 3종**

승격 전에는 실패가 **stderr 문자열 + rc 2** 뿐이라 caller 가 실패 *종류* 를
구분할 수 없었다. 다른 stable skill 과 같은 `ErrorOutput` 형태로 **stdout 에**
emit 하도록 바꿨다 — 기계가 읽는 것이 stdout, 사람이 읽는 것이 stderr 다.

| error_code | 언제 |
| --- | --- |
| `invalid_query_tokens` | `--query-tokens` 가 비어 있다 (구분자만 준 경우 포함) |
| `missing_required_document` | `--workspace-root` 경로 부재 |
| `memory_index_query_runtime_error` | retrieval 중 예외 (entries 손상 등) |

**smoke**

`test_memory_index_query_error_codes` — 앞의 두 code 는 **subprocess 로 실제
실행해** 확인하고, 세 번째(runtime error)는 인위 재현이 불안정하므로 **소스에
선언돼 있는지** 만 본다. 정상 경로에 `error_code` 가 *없는지* 도 함께 확인한다
(있으면 성공을 실패처럼 보고하는 셈이다).
