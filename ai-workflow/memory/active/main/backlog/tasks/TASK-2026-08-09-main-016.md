## 🛠️ Implementation / Content

TASK-015 에서 밝혀진 것: release note 의 `누적 smoke **N/N PASS**` 는 *살아있는
지표* 인데 **그 줄을 적는 일은 순전히 사람 몫** 이었다. 그래서 v1.1.0 / v1.1.1 이
통째로 빠뜨렸고, 그동안 dashboard 는 옛 note(v1.0.0 의 234)를 읽어
`check_smoke_trend_cross` 가 계속 red 였다. **릴리스 절차에 그걸 잡는 자리가
없었다.**

**신설한 것** — `cmd_release` 의 step **3.4** (changelog auto-step 3.5 바로 앞):

```
verify_release_note_smoke_count(version)
  → note 부재            : error
  → `누적 smoke` 줄 부재  : error + "N/N 로 적을 것" 안내
  → 수치 ≠ 현재 파일 수   : error + "전량 결과 확인 후 갱신할 것"
  → 일치                 : ok
```

`--skip-smoke-count-check` escape hatch. dry-run 에서는 결과만 싣고 막지 않는다.

**자동으로 채우지 않는다.** 그 줄은 *전량 PASS 했다* 는 **주장** 이고, 실제로 전량을
돌린 사람만 할 수 있는 말이다. 도구가 대신 적으면 거짓 주장을 만든다 — CHANGELOG
(git log 에서 deterministic 하게 재생성)와 성격이 다르다. 그래서 **빠졌거나 어긋난
것을 알려 주기만** 한다. 회귀 case 9b 가 그 원칙을 고정한다 (함수가 파일을 쓰면 red).

**정규식은 dashboard 와 같은 것을 쓴다** (`SMOKE_COUNT_RE` ↔ `SMOKE_COUNT_PATTERN`).
두 곳이 다른 패턴을 들면 "노트에 적었는데 dashboard 가 못 읽는" 상태가 조용히 생긴다.
