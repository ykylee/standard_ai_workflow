**수동 발행을 택한 이유**

`cmd_release` 의 pre_check 에서 **doctor / state 가 만성 실패** 다
(`testing: non_compliant` / `last_freeze`·`last_ingest` 빈값). git·packaging 은 ok.
`release` 서브커맨드에는 `--skip-doctor` / `--skip-state` 가 없고 `--skip-validate`
뿐인데, 그건 **packaging·git·mypy 검증까지 전부** 건너뛰어 게이트를 무력화한다.
사용자 판단으로 v1.1.2 와 같은 수동 절차(tag + `gh release create`)를 썼다.

**주의 — `release` 의 기본이 apply 다**

`--dry-run` 없이 `release --version 1.1.3` 을 돌렸더니 `=== release (APPLY) ===`
로 진입했다. 다행히 pre_check 의 git dirty 에서 막혀 아무것도 발행되지 않았지만,
**되돌리기 어려운 명령의 기본값이 apply 인 것은 위험하다.** 다른 도구들
(`claim_workspace` / `install_pre_push_hook` / `host_pull_registry`)은 dry-run 이
기본이다. 후속 후보.
