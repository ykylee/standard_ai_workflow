**④ 진짜 병목은 표본이 아니라 증거였다 (이번 세션의 실질 발견).**
두 mypy 게이트 모두 **실패 사유를 버리고 있었다**:

- `exit 2` 는 mypy 의 **blocking error** 이고 사유는 **stderr** 로 나온다.
- 두 게이트의 오류 집계는 stdout 에서 `.py:` + `error:` 형태만 센다. blocking error
  는 그 필터에 안 걸린다 → 남는 기록이 `exit 2 (0 errors)` **한 줄**.
- CI 로그는 만료되고, **annotation 에는 검사 이름조차 안 실린다** (이번에 실측:
  `Process completed with exit code 1` 뿐). 1차가 적어 둔 관찰 방법("로그가 만료돼도
  annotation 은 남는다")이 이 실패 형태에서는 **성립하지 않는다**.

즉 4번 터지는 동안 원인을 못 좁힌 것은 표본이 부족해서가 아니라 **매 사건이 증거
없이 지나갔기** 때문이다. 수리:

- `cmd_validate` 의 mypy 결과에 `stderr_tail` / `stdout_tail` 추가 — **exit≠0 인데
  셀 오류 0건일 때만** 싣는다 (정본 한 곳, 두 게이트가 함께 혜택).
- `check_mypy_strict_ci_v0_11_11` case 8 의 assertion 메시지에 stderr + stdout 말미 첨부.
- 되주입 실증: blocking error 를 흉내내면 `stderr_tail` 에 사유가 그대로 실린다.

**⑤ 유력 가설 (미확정, 다음 재발이 판정한다)**: 전량은 병렬이라 다른 check 가 스캔
