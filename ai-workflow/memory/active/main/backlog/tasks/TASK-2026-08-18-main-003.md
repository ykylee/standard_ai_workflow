  - **실측 red 3건**
    - `wk wiki-emit` — `<git루트>/workflow-source/tools/refresh_wiki_memory.py` 를 부른다. 그 파일은 **어디에도 없다** (v1.1.8 에 `workflow_kit/tools/` 로 옮겼고 v1.2.0 에 구경로 shim 을 drop, TASK-2026-08-13-main-005). 배포본이 아니라 **이 저장소에서 지금 죽는다**: `can't open file .../workflow-source/tools/refresh_wiki_memory.py`.

  - **같은 패턴, 미실행 확인**: `seed-workspace-memory`(`SOURCE_ROOT/scripts/generate_workflow_state.py`, "생성기 부재" 로 graceful degrade) · `claim-workspace`(`SOURCE_ROOT/workflow_kit/tools/seed_workspace_memory.py` 를 **파일 경로로** 실행 + `PYTHONPATH=SOURCE_ROOT`) · `score-wiki-trend`(같은 방식, 현재는 조용히 `(empty history)`) · `session-start`(archive 분기에서만 — **기본 경로는 정상**, 소비자 프로젝트에서 확인) · `fill-reverse-engineering-artifacts`(`SOURCE_ROOT/reverse-engineering` 템플릿).
  - **무해로 판정**: `SOURCE_ROOT` 를 `sys.path.insert` 에만 쓰는 다수(`doc_sync`·`backlog_update`·`refresh_state` 등)는 없는 경로를 넣는 no-op 이고 설치본에서 import 는 정상 해결된다. 저장소 개발 전용(`release_pipeline*`·`check_packaging`·`release_status`·`migrate_*`)도 대상 밖.
