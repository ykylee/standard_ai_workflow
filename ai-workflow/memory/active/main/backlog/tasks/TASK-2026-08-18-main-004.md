## 🛠️ Implementation / Content

- 진행 현황: `wk wiki-emit` 의 경로 결함을 고치자(TASK-2026-08-18-main-003) 비로소 드러난 하위 결함이다 — 그 전에는 wrapper 가 `can't open file` 로 죽어 하위 단계가 **한 번도 실행되지 않았다**. 2026-08-18 실측, 서로 다른 원인 2건:
  - **1단계 `refresh_wiki_memory --refresh-raw`** — `update_state_json` 이 `data["memory"]["last_freeze"]` 를 쓰는데 현재 `state.json` 에 `memory` key 가 없다 (`KeyError: 'memory'`). state.json 스키마가 그 사이 바뀌었다.
  - **2단계 `emit_wiki_l2_body`** — L1 미러를 `RAW_MIRROR/<project>/ai-workflow/wiki/` 아래로 가정하는데 실제로는 `ai-workflow/wiki/` 다 (`ValueError: … is not in the subpath of …/standard-ai-workflow/ai-workflow/wiki`). 레이아웃이 그 사이 바뀌었다.
  - **3단계 `--emit-l2`(stub last_touched) 는 `rc=0` 이지만 정상이 아니다** — 진단 실행 한 번으로 `ai-workflow/wiki/sources/` 4개의 `last_touched` 가 **2026-07-22 → 2026-06-14 로 뒷걸음쳤다**(`--since` 기본값 2026-06-10 을 그대로 찍는다). 그 결과 wiki score 의 `lifecycle` 이 5.0 → 0.0 이 되고 `check_wiki_trend` 가 red 가 된다. 2026-08-18 세션에서 `git checkout` 으로 원복했다. rc=0 이라 **조용히 퇴행시킨다** — 세 단계 중 가장 위험하다.
  - 참고: `path_in_active` 의 docstring 이 "규칙을 복사해 둔 caller 가 layout 변경을 놓치는 것이 `refresh_wiki_memory` red 의 원인이었다" 고 이미 적고 있다 — 같은 자리에서 또 났다.
