## 🛠️ Implementation / Content

- 진행 현황: `2026-08-18 12:04` 기준 실측 완료

  **① SPEC 이 v0.2 로 움직였다 (가장 큰 발견).** ADR-006 은 2026-06-16 에 v0.1 을 고정했는데 `okf/SPEC.md` 는 현재 **v0.2** 다. 변경 3가지: `timestamp` → `generated.at` · `# Citations` 본문 절 → `sources` frontmatter(+ `sources[].id` 를 라벨로 쓰는 footnote) · **`status` 가 정규 필드로 승격**(값 `draft|stable|deprecated`). 우리는 셋 다 v0.1 형태다. 앞의 둘은 v0.2 가 legacy fallback 을 SHOULD/MAY 로 열어 둬서 **읽히긴 한다**.

  **② `status` 는 다르다 — 값 충돌이다.** v0.1 에서 `status` 는 unknown key 라 관용 대상이었는데 v0.2 에서 정규 필드가 됐다. 우리 번들 71장의 값 분포는 `active` 42 · `accepted` 25 · `draft` 2 · `proposed` 1 — **`draft` 2장만 v0.2 어휘 안에 있고 나머지 69장은 밖이다.** SPEC 은 "consumers MUST NOT reject a bundle because of **unknown additional frontmatter keys**" 라고만 보장한다. `status` 는 더 이상 unknown key 가 아니므로 그 보장이 안 걸린다 — v0.2 소비자가 `stable` 필터를 걸면 우리 문서는 전부 빠진다.

  **③ 다른 생산자와 실제로 읽히는가 — 부분적으로 그렇다.** 공통: 둘 다 루트 `index.md` frontmatter 에 `okf_version: "0.1"` 선언(**openwiki 도 v0.1 에 머물러 있다**) · `index.md` 를 예약 비개념 문서로 사용 · **둘 다 `log.md` 를 안 낸다** · `type`/`title`/`description`/`tags` 사용 · 교차 링크는 평범한 상대 마크다운 링크. 즉 소비자는 양쪽을 읽을 수 있다.

  **④ 그런데 `type` 으로는 라우팅이 안 된다 (SPEC 자체의 한계).** 우리는 닫힌 enum(`concept` 27 · `decision` 25 · `entity` 13 · `pattern` 4 · `retrospective` 1), openwiki 는 자유 산문(`Architecture overview`). SPEC 이 `type` 을 "non-empty string, no registry" 로 정의하므로 **둘 다 적합하고, 그래서 교차 생산자 라우팅은 원리적으로 불가능하다.** 공유 어휘가 없다. 이건 어느 쪽의 결함도 아니다.

  **⑤ 출처(provenance)도 이식되지 않는다.** 우리는 `last_ingested_from` → Citations 절/`resource`, openwiki 는 **아무 출처 필드도 안 낸다**(본문 인라인 링크뿐, `timestamp` 도 없음). v0.2 의 `sources` 가 이 자리를 메우라고 생긴 것이다.

  **고친 것 2건 (값싸고 확실한 것만)**
  - `# Citations` 를 **h1** 으로. 우리는 `##`(h2) 로 내고 있었다 — v0.1 SPEC §8 이 h1 이고, v0.2 의 legacy fallback 문구도 `# Citations` 를 지목한다. **h2 면 v0.1 에서도 비표준이고 v0.2 소비자의 fallback 경로에서도 안 걸린다.** 18 cases 중 아무도 이 자리를 재지 않았다.
  - wiki score 대시보드가 **frontmatter 없이 생성**되고 있었다 — export 가 71장 중 1장을 `no frontmatter` 로 **조용히 건너뛰었고**, wiki lint 는 V-1(위치)·V-4(index)만 보므로 아무도 몰랐다. 생성물이라 손으로 고치면 되돌아가므로 **템플릿이 frontmatter 를 내게** 했다. 이제 71/71, skip 0.
  - `check_okf_export` 18→20 cases: h1 Citations 고정 + **자기 적용**(이 저장소 wiki 가 한 장도 안 빠지고 export 되는가). 되주입 2종 red 실증.

  **안 고친 것 (판단이 필요하다)**: v0.2 이행. ADR-006 이 v0.1 을 명시적으로 고정했으므로 새 ADR 없이 바꾸지 않는다. 이행 범위는 `generated.at`·`sources`·`status` 어휘 3건이고, 그중 **`status` 만 실질 위험**이다.
- 다음 세션 시작 포인트: v0.2 이행 여부를 ADR 로 판단한다. 최소안은 `status` 어휘만 매핑(`active`/`accepted` → `stable`, `proposed` → `draft`)하고 우리 어휘는 확장 키로 보존하는 것.
- 남은 리스크: openwiki 도 v0.1 에 머물러 있어 **지금 당장의 상호운용 손실은 없다**. 위험은 v0.2 소비자가 등장할 때 발현한다.
