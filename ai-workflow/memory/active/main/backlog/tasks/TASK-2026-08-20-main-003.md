- 작업 결과: **ADR-026 채택 — `okf_version` 0.1 → 0.2, legacy 를 남긴 채 정규 필드를 더한다.** SPEC 원문(1003줄) §13 을 직접 대조했다: breaking 2건에 **둘 다 소비자 fallback 이 명시**돼 있고 나머지는 전부 additive라, **한 번들이 v0.1·v0.2 소비자를 다 만족**한다. ① **`status` 어휘 매핑** — v0.1 에서는 정규 필드가 아니어서 우리 값을 그대로 실어도 됐지만 v0.2 에서 승격되면서 §11 의 관용 보장(unknown key 한정) 밖이 됐다. `active`/`accepted`→`stable`, `proposed`/`draft`→`draft`, `superseded`/`deprecated`→`deprecated`, 원문은 `wiki_status` 확장 키로 보존. **생략은 답이 아니다** — §5.4 가 `Absent status ⇒ stable` 이라 생략이 곧 stable 주장이다; 어휘 밖 값은 가장 보수적인 `draft` 로 내린다. ② **`sources` emit** — `last_ingested_from` 이 정확히 §5.1 이 말하는 재료이고, entry 의 `resource` 는 번들 상대 경로·범위 서술도 허용하므로 **in-repo 출처가 처음으로 기계가 읽는 필드**에 들어간다. ③ **`generated` 는 채택하지 않는다** — §5.2 가 `generated.by` 를 REQUIRED 로 두는데 우리는 페이지별 actor 기록이 없다. 도구 이름은 "도구가 내용을 썼다" 는 거짓이고 `human:` 은 생성물 페이지까지 사람 것으로 만들어 §5.3 trust tier 를 부풀린다. §13.1 의 `timestamp` fallback 이 덮으므로 비워 두는 편이 정확하다. ④ **이행이 드러낸 결함: 소비자가 v0.1 을 거부하고 있었다.** ADR-011 정책이 `older → error` 였는데 우리가 v0.1 인 동안에는 **도달 불가능한 분기**라 아무도 안 밟았다. v0.2 로 올리는 순간 살아나 **v0.1 번들 전부를 거부** — 48차에 실측으로 상호운용을 확인한 openwiki 가 정확히 v0.1 이다.
