## 결정과 근거

1. **형식·청중**: 강의 60분 + Q&A, AI 코딩 도구 입문자 중심. 기존 자산과 무관하게
   완전히 새로 작성 (사용자 확정).
2. **컨셉**: "매일 아침 기억을 잃는 신입 + 당신은 그 신입의 PL". 4개 후보 중
   사용자가 온보딩 은유를 선택했고, 이후 구술로 PL 프레임이 추가되며 무게중심이
   도구 중심 → 사람(리더) 중심으로 이동.
3. **v1 → v2 재설계**: 발표자 구술 4회분이 전부 인과 사슬이라 시간순 뼈대(첫날/
   둘째날/수습)를 버리고 사슬을 척추로. 은유는 액자로만 유지. 확정 사슬:
   PL → 위임·확인 2다이얼 → 기억 → 탐색 실패 → 중복·중구난방 → 대안 →
   워크플로우 명명 → 기록 진실성 검증 → "자기 없이 굴러가게".
4. **핵심 설계 장치**: "워크플로우" 명명은 문제 완성 직후(슬라이드 27, 정의가
   결론이 되도록) / 슬라이드 11(확인이 저절로 걸린다)이 복선, 42가 회수 /
   결론부에서 은유 3지점을 직접 부순다(안 배움·안 물음·신뢰 비누적).
5. **사례 3건**: 저장소 postmortem 번역 — 규약 4곳 복제 / reader-writer 절반 이관 /
   미분류→done fallback. 내부 명칭은 슬라이드 미노출, 발표자 노트에만.
6. **구술의 빈칸 1건 보충**: 중복 작업은 메모리·위키(사후 기록)로 못 막는다 →
   **작업 등록(백로그, 사전 공개)** 을 대안 목록에 추가.
