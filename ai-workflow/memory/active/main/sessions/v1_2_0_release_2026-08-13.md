## 이 릴리스의 실측 결론

**wheel top-level = `['workflow_kit']`** (zipfile 실측 + `check_packaging` PASS).
`tools`/`bootstrap_lib` 라는 일반명이 site-packages 충돌을 일으켜 PyPI 를 막고
있었는데, 그 사유가 사라졌다 — **남은 것은 정책(소유자 결정) 뿐**이다.
재유입 방지는 `check_packaging.FORBIDDEN_IMPORTS` 가 wheel 실측으로 강제한다.

## shim 을 지우자 드러난 것

구경로 shim 이 있는 동안은 아무도 몰랐던 소비자 **10곳**이 red 로 드러났다:
`workflow_kit_cli` in-process wrapper 2 / `cli_commands_cache`·
`cli_commands_release`·`release_status` 의 sys.path 주입 / `claim_workspace`·
`score_wiki_trend`·`score_wiki_maintainability`·`consumer_metrics`·
`session_start` 의 경로 상수. **shim 은 호환을 준 게 아니라 의존을 숨기고 있었다.**

**검사 무력화 1건** (`check-neutralized-not-broken` 계열): `check_entry_points`
[4] 가 v1.1.8 개명 이후 `-m tools.tools.X` 를 돌리고 있었고, 그
`ModuleNotFoundError` 의 rc=1 이 허용 범위 `(0, 1)` 에 들어 **36개 전부 통과**로
보고했다. module path 를 entry point target 에서 직접 취하도록 고치고,
`No module named` 는 rc 무관 실패로 판정하는 [4c] 를 신설했다.

## 릴리스 직후 재실행이 잡은 것 (3건)

v1.1.7·v1.1.4 와 같은 계열. **발행 후 전량 재실행이 절차의 일부인 이유**다.

1·2. `check_code_index` / `check_document_index` 의 `EXPECTED_LAST_UPDATED`
하드코딩 상수 (2026-08-12) — `doc-headers-update` 가 문서를 2026-08-13 으로
올렸다. 하드코딩은 의도(문서가 조용히 늙는 것 방지)이므로 상수를 올렸다.

3. **`check_standard_single_source` 배포 사본 23건 드리프트** — `doc-headers-update`
가 정본 `workflow-source/core/*.md` 만 고치고 `ai-workflow/core/*.md` 사본을
몰랐다. 사본 byte 동일은 저장소 규약이고 검출기도 이미 있었는데, **없던 것은
만드는 층의 규약 인지**였다 (`derivative-writer-must-know-the-rule`).
→ `_sync_distributed_core_mirror()` 신설 + `cmd_doc_headers_update` 가 core
scope 일 때 호출 + 반환에 `distributed_core_synced` 노출.
→ `check_release_pipeline` 에 sandbox 되주입 test 신설 (**결함 코드에서 FAIL,
복원 후 9/9 실증**). 손으로 두 번 고치지 않게 만드는 층에 규약을 심었다.
