- 문서 목적: task 레코드를 읽는 쪽의 계약을 하나로 모으고, 그 과정에서 드러난 조용한 결함을 남긴다.
- 범위: `project_docs` 의 task 파싱, index 방언, frontmatter 우선, `check_task_ssot_source`
- 대상 독자: AI agent, 저장소 관리자
- 상태: active

## 0. 전수 조사가 먼저였다 — 그리고 조사가 결함을 찾았다

완료 기준의 첫 항목이 "현 형식을 읽는 자리를 전수 조사" 였다. 조사 자체가 **살아 있는
결함 셋**을 드러냈고, 1단계는 그것을 닫는 일이 됐다.

## 1. 같은 필드에 소스가 둘이었다

| 읽는 쪽 | 소스 |
|---|---|
| `archive_branch_memory`, `check_task_status_axis_separation` | frontmatter `status:` |
| `parse_backlog` (state.json 생성기의 입력) | 본문 `- 상태:` |

실측 277개 task 파일:

- 불일치 **0건**
- 그런데 **본문 줄이 없는 것 105개(38%)** — legacy 마이그레이션 산출물이다

즉 위험은 "두 값이 다르다" 가 아니라 **"한쪽이 아예 없다"** 였다. 그 105개는 파서에게
*상태 없음* 이었고, 어느 목록(in_progress / blocked / done)에도 안 들어갔다.

**frontmatter 를 우선**하도록 고쳤다. 디스크의 본문은 건드리지 않는다 — 합성한 줄
목록에서만 본문 상태 줄을 빼고 frontmatter 값을 헤더 뒤에 넣는다. 소비자 저장소의
기존 리더는 본문을 계속 본다 (2년 compat).

> 처음엔 헤더 뒤에 **끼워 넣기만** 했는데, 파서가 뒤에 오는 값으로 덮어써서
> 본문이 이겼다. case 1 이 그걸 잡았다.

## 2. index 방언이 셋이고 둘이 안 보였다

| 방언 | 모양 | 파서가 봤나 |
|---|---|---|
| 링크 (신형) | `path:` 뒤에 마크다운 링크 (`./tasks/X.md` 를 label 과 target 양쪽에) | ✅ |
| 백틱 (v0.14.0 마이그레이션) | `` path: `backlog/tasks/X.md` `` | ❌ |
| 인라인 (legacy 분할) | `path:` 자체가 없음 | ❌ |

`active/main` 의 daily index **20개가 task 를 0개로 읽고 있었다.** 파일은 그대로 있는데
어느 집계에도 안 나타난다. **그 0 은 "그 날 한 일이 없다" 로 읽힌다.**

세 방언을 모두 해석하게 했다. 결과: 0개 index **20 → 0**, 읽힌 task **262개**,
상태 없는 task **0개**.

## 3. fallback 이 두 겹으로 죽어 있었다

"index 가 없으면 `tasks/` 를 글롭한다" 는 fallback 이 있었는데 **두 이유로 절대 안
돌았다**:

1. glob 패턴이 `<stem>_*.md` — 실제 파일명은 `TASK-<date>[-<slug>]-<NNN>.md` 라
   **아무것도 매칭하지 않았다**
2. `WorkflowDocParser.__init__` 이 파일을 즉시 읽어 **부재 파일에서 먼저 죽었다** —
   fallback 코드에 도달할 수가 없었다

둘 다 고쳤다. 있으나 마나인 코드가 있으나 마나인 채로 몇 달을 갔다.

## 4. 되주입이 case 하나를 무력화 상태로 드러냈다

백틱 해석을 통째로 제거했는데 **아무 case 도 실패하지 않았다.** case 5 가 index 와
같은 날짜의 파일명을 써서, 백틱이 안 되면 `tasks/` glob fallback 이 같은 파일을
집어 그대로 통과했기 때문이다 — **자기가 말하는 것을 재지 않는 case** 였다.

날짜를 다르게 해 격리했더니 이번엔 fixture 디렉터리 구조 때문에 실패했다. 구형 백틱
경로는 저장소 상대(`backlog/tasks/X.md`)라 실물처럼 `<...>/backlog/` 아래여야 해석된다.
**fixture 를 실물 모양으로** 고쳤다 — 오늘 같은 실수 두 번째다 (handoff 롤오프에서는
한 줄짜리 기준선만 재다가 하위 줄을 고아로 남겼다).

## 5. 남은 것 — 2단계 이후

1단계는 **읽는 쪽**을 하나로 모았다. 아직 구조화되지 않은 것:

- **쓰는 쪽의 반복 필드** — `--done-criteria` 를 여러 번 줘도 마지막 하나만 남고,
  다중 줄 우회책은 update 때마다 줄을 중복시킨다 (오늘 두 번 밟았다).
- **본문 라벨의 영어화** — 라벨이 파싱 계약에서 빠진 뒤라야 안전하다. 1단계가 그
  선행 조건을 절반 만들었다 (status 는 frontmatter 가 정본).
- `state.json` 산출은 **전후 동일** 하다 — 최신 backlog 는 이미 신형 방언이라
  회귀 없이 과거 커버리지만 늘었다.
