# 세션 기록 — `--changed` 선택 실행 (2026-08-14)

- 문서 목적: 변경 범위 기반 선택 실행의 계약과 그 계약을 지키는 장치를 남긴다.
- 범위: `run_all_checks --changed`, `WATCHES` 선언, `check_changed_selection`
- 대상 독자: AI agent, 저장소 관리자
- 상태: active
- 관련 문서: [task](../backlog/tasks/TASK-2026-08-14-perf-changed-selection-001.md)

## 0. 이 기능의 실패 양식은 "느려짐" 이 아니다

선택 실행이 잘못되면 **조용히 안 도는 검사**가 생긴다. 러너는 여전히 green 을 찍고
사람은 "전부 돌았다" 로 읽는다. 그래서 설계 전부가 그 한 가지를 막는 쪽으로 기울어 있다.

| 계약 | 이유 |
|---|---|
| **미선언 = 항상 실행** | 선언을 깜빡한 check 는 느려질 뿐 놓치지 않는다 |
| **자기 파일이 바뀌면 무조건 실행** | 선언 자체를 고친 경우를 포함한다 |
| `WATCHES` 원소가 하나라도 리터럴이 아니면 **미선언 취급** | 반쯤 읽은 선언으로 건너뛰는 것이 곧 사각지대 |
| parse 실패 파일도 **실행** | 건너뛰지 말고 실패하게 둔다 |
| 건너뛴 것은 **이름과 사유를 전부 출력** | 조용한 축소는 "전부 돌았다" 로 읽힌다 |
| 변경 0건이면 **아무것도 안 돌리고 "통과가 아니라 잴 것이 없음"** 이라고 찍는다 | 0개 실행을 통과로 오독하지 않게 |
| 출력마다 `이 실행은 게이트가 아니다` | push 직전은 전량 2축이다 |

선언을 **check 파일 안**에 두는 이유는 `REQUIRES_QUIET_REPO` 와 같다 — 목록을 러너
안에 두면 파일에서 멀어져 드리프트하고, 그 드리프트가 곧 사각지대다.

## 1. 계약을 fixture 로 못 박았다 (`check_changed_selection`, 9 cases)

**양방향이다.** case 3 은 *관련 변경을 잡는가*, case 4 는 *무관한 변경을 건너뛰는가*.
한 방향만 재면 "아무것도 안 잡는" 구현이 통과한다 — `check_archive_history_integrity`
case 14 와 같은 부류다.

되주입 2종으로 실증했다 (복원은 사본 백업으로 — `git checkout` 은 미커밋 작업을 지운다):

| 심은 결함 | 잡은 case |
|---|---|
| 매칭을 항상 거짓으로 (선언 범위를 놓친다) | case 3 FAIL |
| 미선언도 건너뛰게 (사각지대를 만든다) | case 1 · 5 · 6 FAIL |

## 2. 선언은 7개에만 붙였다 — 하나는 일부러 안 붙였다

무거운 8개 중 7개에 `WATCHES` 를 달았다. **`check_no_repo_write` 는 선언하지 않았다**:
감시 표본 13종을 서브프로세스로 돌리므로 관찰 범위가 사실상 저장소 전체다. 좁게 적으면
그게 곧 사각지대라, 미선언(=항상 실행)이 정직한 답이다.

`check_wiki_score` 도 좁히지 않았다 — operational dim 이 `SMOKE_TESTS` 의 check 들을
돌리므로 `workflow-source/tests/*` 를 통째로 관찰 범위에 넣었다.

## 3. 실측 — 메모리 문서 1건만 편집한 경우

```
실행 250 / 건너뜀 6      벽시계 125.9s  (전량 154.2s 대비 −18%)
```

건너뛴 6개가 정확히 무거운 것들이다 (`wiki_score` / 릴리스 계열 4 /
`mypy_config_actually_loaded`). 절감의 크기는 **무엇을 고쳤는지에 달린다** — 코드를
만지면 그것들이 도로 들어온다. 그게 맞는 동작이다.

## 4. 부수 — 검사를 하나 늘리면 선언된 개수 3곳이 어긋난다

새 check 하나를 추가하자 `CODE_INDEX` / `INSTALLATION_AND_USAGE` / 릴리스 노트 누적
수치가 255 를 주장해 red 가 됐다. 저장소가 "개수를 선언으로 고정" 하는 규약을 갖고
있기 때문이고, 그 규약이 제대로 작동한 것이다. 256 으로 갱신했다.
