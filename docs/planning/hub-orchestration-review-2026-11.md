## 0. 한 줄 결론

> 2.0 허브는 task · handoff · 이력의 **정본**이지만, 일을 **나눠 주지는 못한다** — 세션이 스스로 와서 읽어 갈 뿐이다.
> 이 축은 그 위에 **세션을 아는 층**을 얹는다: 중앙 허브가 세션 목록 · 상태 · 받은편지함 · 오케스트레이터 lease 를 갖고,
> PC 마다 뜨는 **중계 허브**가 그 PC 의 하네스 세션을 띄우고 · 이어 가고 · 메시지를 넣는다.
> 사람이 선언한 **메인 오케스트레이터 세션**은 허브 도구로 세션 상태를 보고, task 를 배정하고, 새 세션을 요청한다.
> 가장 어려운 문제는 **대화형 세션은 바깥에서 말을 걸 수 없다**는 것이고 (§3), 그래서 전달은 "끌어오기 · 중계가 띄운 세션 · 사람 넘김" 세 길로 나뉜다.
> 이것은 2.0 의 D5 · R15.3 (A2A 는 첫 판에서 뺀다)과 kit 의 "중앙은 하네스에 메시지를 보내지 않는다"(§0.6)를 **다시 여는** 일이다 (§8).

## 1. 배경 — 지금 있는 것과 없는 것

| 층 | 있는 것 | 없는 것 |
|---|---|---|
| 중앙 (2.0 허브) | 프로젝트 · 콜사인(작업 환경 = 클론 하나) · task(`assignee` = 콜사인) · handoff · 이력 · 결정 응답(승인된 human 만) · 원격 MCP · 화면 `/ui/` | **세션** 개념 (콜사인 아래 동시에 도는 여러 세션) · 받은편지함 · 배정의 전달 · 상태(쉬는 중 / 일하는 중) |
| PC | 선택 클라이언트 `hub_client.py` (표준 라이브러리 한 파일 — 보낼편지함 · 캐시 · 부트스트랩) | 상주 프로세스 · 세션 감독 · 로컬 화면 |
| 하네스 | 진입 파일 · 원격 MCP 등록 · (Claude Code) hook | 바깥에서 턴을 일으키는 길 (§3) |
| 1.x 유산 | workspace registry(`host_id`) · federation 읽기 · push 선점 · contract v1 (세션 **안** 위임) | — |

1.x 의 다중 워크스페이스 설계는 일부러 **지시를 전달하지 않았다** — "지시는 워크스페이스에 놓이고 세션이 읽는다"(§0.6 · §5A.1).
2.0 허브도 그 원칙을 이어 받아 A2A 를 첫 판에서 뺐다 (D5). 이번 요청은 그 다음 단계 — **허브가 세션을 알고, 오케스트레이터가 일을 나눠 준다**.

## 2. 4계층 모델

| 계층 | 실체 | 식별자 | 몫 |
|---|---|---|---|
| **중앙 허브** | 지금의 2.0 허브 (Python · SQLite, 서버 하나) | `hub_id` | 정본 — task · 배정 · 세션 목록 · 받은편지함 · 오케스트레이터 lease · 이력. 판정은 지금처럼 kit 함수 |
| **PC 중계 허브** | PC 마다 하나 뜨는 상주 프로세스 (새로) | `host_id` (중앙 발급 — 1.x registry 의 결정 그대로: hostname · IP 는 표시용) | 그 PC 의 세션 감독(띄우기 · 이어 가기 · 멈추기) · 메시지 넣기 · 로컬 파일 쓰기 대행 · 오프라인 보낼편지함 · 로컬 화면 |
| **하네스** | Claude Code · Codex · MiniMax Code · Antigravity … | 하네스 이름 + 판 | **어댑터**가 차이를 가둔다 — 띄우기 · 이어 가기 · 넣기 · 상태 읽기 4동작 |
| **세션** | 하네스의 대화 하나 | `session_id` (중앙 발급) + 하네스 세션 ID | 일 단위. 상태 `idle` · `working` · `waiting_human` · `ended` · `unknown` (재지 못함 — 통과로 세지 않는다) |

- **콜사인과의 관계** — 콜사인은 지금처럼 *작업 환경*(클론)이고, 세션은 그 아래 여럿이다. PC 하나에 콜사인 여럿, 콜사인 하나에 세션 여럿.
  작업 기억(handoff)은 지금처럼 콜사인 단위로 두고, 세션은 **배정 · 전달 · 상태**의 단위로만 쓴다 (기억을 세션까지 쪼개면 세션이 끝날 때마다 고아가 생긴다).
- **연결 방향** — 중계는 중앙으로 **나가는 연결만** 연다 (긴 폴링 또는 SSE). 중앙이 PC 로 들어오지 않는다 — 방화벽 · NAT 뒤 PC 도 그대로 참여하고, 중앙이 PC 를 직접 조작하는 길이 생기지 않는다.
- **중계 없는 참여** — 중계가 없는 PC(또는 클라우드 세션)도 지금처럼 원격 MCP 만으로 참여한다. 그런 세션은 "끌어오기"(§3 T1)로만 일을 받는다.

## 3. 세션에 일을 전하는 방식 — 핵심 난제

대화형 하네스 세션은 **사람의 입력으로만 턴이 시작된다**. 쉬고 있는 세션에 바깥에서 말을 거는 표준 길이 없다.
그래서 전달은 세 길로 나뉘고, 세션마다 어느 길인지 허브가 기록한다.

| 길 | 방식 | 깨울 수 있나 | 필요한 것 |
|---|---|---|---|
| **T1 끌어오기** | 세션이 턴 경계(세션 시작 · 사용자 입력 직전 · 턴 끝)에 `hub_inbox` 를 읽는다 — 진입 규칙 + hook | ❌ 다음 턴까지 기다린다 | 원격 MCP 만 (중계 불필요) |
| **T2 중계가 띄운 세션** | 중계가 하네스를 **비대화형**으로 띄우고, 메시지가 오면 같은 세션을 이어 간다 | ✅ | 중계 + 하네스의 비대화형 · 이어 가기 수단 |
| **T3 사람 넘김** | 사람이 보는 대화형 세션 — 다음 턴에 hook 으로 끼우고, 쉬는 중이면 로컬 화면 · OS 알림으로 사람에게 알린다 | 사람이 깨운다 | 중계(알림) 또는 화면 |

- **전달 보장** — 적어도 한 번 + `request_id` 로 중복 제거 (2.0 보낼편지함과 같은 규칙). 세션이 읽으면 `ack`, 배정을 받아들이면 task 가 `in_progress` 가 된다. 응답 없는 배정은 lease 만료 뒤 오케스트레이터에게 되돌아온다.
- **메시지는 데이터다** — 받은 세션은 다른 세션의 메시지를 *지시가 아니라 동료가 보낸 자료*로 다룬다. 출처(보낸 세션 · 오케스트레이터 여부)를 붙여 전하고, 권한 바꾸기 · 되돌릴 수 없는 일은 메시지만으로 하지 않는다 (§7).

**하네스별 제어 수단 — 전부 미측정.** 아래는 후보이며 requirements 단계에서 실측(S 계열)으로 확정한다. 재지 못한 칸은 "지원"으로 세지 않는다.

| 하네스 | T1 hook 후보 | T2 비대화형 · 이어 가기 후보 | 상태 읽기 후보 |
|---|---|---|---|
| Claude Code | `SessionStart` · `UserPromptSubmit` · `Stop` hook (1.x compact 중계가 이미 hook 3종을 쓴다) | `claude -p` · `--resume` · 스트림 입출력 · Agent SDK | hook 이벤트 · 스트림 출력 |
| Codex | 플러그인 hook (1.x 에 실측 기록 있음 — `failed` 판정 함정, 메모리 참조) | `codex exec` · `exec resume` | 출력 · rollout 파일 |
| MiniMax Code · Antigravity | 미조사 | 미조사 | 미조사 |

## 4. 메인 오케스트레이터

### 4.1 선언

- **사람이 지정한다** — 승인된 human 콜사인(owner)이 프로젝트에 오케스트레이터 세션 **하나**를 지정한다. 세션이 스스로 오케스트레이터가 되지 않는다.
- **lease** — 지정은 만료 시각이 있는 lease 다. 오케스트레이터 세션이 갱신하고, 끊기면 허브가 lease 를 풀고 사람에게 알린다. 동시에 둘은 없다 — 허브가 원자적으로 막는다 (1.x 의 push 선점이 하던 일을 허브 DB 가 한다).
- **인계** — 사람이 다른 세션으로 옮긴다. 옛 오케스트레이터의 미완 배정은 목록째 넘어간다.

### 4.2 권한 — 단계로 나눈다

| 단계 | 할 수 있는 것 | 기본값 |
|---|---|---|
| 보기 | 프로젝트의 세션 목록 · 상태 · 배정 · 진척 · handoff | 켬 |
| 배정 | task 를 세션(또는 콜사인)에 배정 · 회수 | 켬 |
| 메시지 | 세션에 메시지 (T1 · T2 · T3 로 전달) | 켬 |
| 세션 요청 | 중계에 새 세션 띄우기 요청 — 어느 PC · 콜사인 · 하네스 | **사람 승인마다** (O4) |
| 멈춤 요청 | 세션 중단 요청 | **사람 승인마다** (O4) |

**하지 못하는 것** (기존 원칙 그대로): 결정 응답(승인된 human 만), done 게이트 · WBS 게이트 우회, 남의 작업 지우기 · 덮어쓰기, 토큰 · 비밀 다루기, 공유 지침 판 올리기(사람만 — 에이전트는 제안).

### 4.3 분배 흐름

```
[오케스트레이터]  허브에서 열린 task · 세션 상태 읽기 → 고르기
        ↓ hub_assign(task, session)         ← 허브가 원자적으로 배정 (이미 배정됐으면 409)
[중앙 허브]  받은편지함에 배정 메시지 → 세션의 전달 길(T1/T2/T3)로
        ↓
[작업 세션]  ack → task in_progress → 지금처럼 progress-note · 계획 · 검사
        ↓ 끝나면 hub_report(task, 결과 요약)
[오케스트레이터]  검토 (verifier 를 오케스트레이터 쪽 세션 안에서) → done 은 지금의 done 게이트가 판정 → 다음 배정
```

- **contract v1 과 섞지 않는다** — 세션 **안**의 위임(subagent)은 contract v1 그대로이고, 오케스트레이터는 세션 **사이**만 다룬다 (`multi_workspace_orchestration.md` §5 의 원칙).
- **진척은 이미 있는 칸으로** — 새 상태 칸을 만들지 않고 task 의 `status` · `progress_note` 와 handoff 를 쓴다. 오케스트레이터가 보는 화면은 그 칸들의 모음이다.

## 5. PC 중계 허브

### 5.1 하는 일

1. **중앙 연결** — `host_id` 로 등록, 나가는 연결 하나로 그 PC 앞 메시지 · 세션 요청을 받는다.
2. **세션 감독** — 하네스 어댑터로 세션을 띄우고 · 이어 가고 · 멈춘다. PC 당 동시 세션 상한 · 하루 턴 상한을 지킨다.
3. **전달** — T2 세션에는 직접 넣고, T3 세션에는 hook 이 읽을 자리에 두고 사람에게 알린다.
4. **로컬 파일 대행** — 원격 MCP 가 못 하는 로컬 쓰기(2.0 의 쓰기 지시 + 해시 확인, I1)를 중계가 하면 에이전트 손을 거치지 않는다.
5. **오프라인** — 중앙이 닿지 않으면 쌓고 나중에 보낸다 — `hub_client.py` 의 보낼편지함을 흡수한다.
6. **로컬 화면** — `127.0.0.1` 에서 그 PC 의 세션 · 받은편지함 · 승인 대기를 보여 준다 (§6).

### 5.2 PC 에 무엇을 까나 (O3)

| 안 | 내용 | 득 | 실 |
|---|---|---|---|
| **A 한 파일** | `hub_client.py` 를 키운 표준 라이브러리 한 파일 (http.server · subprocess) | H4 · R0.4 그대로 (kit 없음) | 화면 · 인증 · 어댑터를 표준 라이브러리로 다시 짠다 |
| **B kit 설치** | `workflow_kit[relay]` — 중앙 허브 코드(ASGI · 인증 · 화면)를 재사용 | 구현이 짧고 중앙과 같은 코드 | 중계를 쓰는 PC 는 kit 을 깐다 |

**권고: B.** 중계는 *선택 계층*이다 — 프로젝트에 **참여**하는 데는 지금처럼 kit 이 필요 없고(H4 유지), 세션을 **띄우고 감독**하려는 PC 만 중계를 깐다.
세션 감독은 그 PC 에서 프로세스를 만드는 일이라 어차피 설치가 필요하고, 표준 라이브러리로 두 벌을 짜면 갈라진다 (규약 단일 출처).

## 6. 화면 3안

| 안 | 실체 | 언어 | 득 | 실 |
|---|---|---|---|---|
| **로컬 웹** | 중계가 `127.0.0.1` 로 서빙, 중앙 허브 `/ui/` 자산 재사용 | Python + 정적 HTML/JS (지금 허브 화면과 같음) | 바로 되고 · 어느 OS 든 · 휴대폰에서도 (LAN 열 때) | 브라우저 탭 하나 더 |
| **VS Code 확장** | 사이드바 · 상태 표시줄 · 로컬 웹을 webview 로 | **TypeScript** (확장 껍데기) | 작업하는 그 창에서 세션 · 승인 대기를 본다 | **PURPOSE 제외 영역**(non-Python runtime) · 마켓 배포 · 판 관리 |
| **스탠드얼론 앱** | 트레이 아이콘 + 창 | Electron/Tauri(비 Python) 또는 pywebview(Python) | 알림 · 자동 시작 | 로컬 웹 + OS 자동 시작으로 대부분 대신된다 · OS 3종 패키징 |

**권고 순서: 로컬 웹 → VS Code 확장 → 스탠드얼론은 보류.** VS Code 확장은 로컬 웹을 띄우는 **얇은 껍데기**로 두어 화면 로직을 한 벌로 유지한다 —
로직이 TS 로 넘어가지 않으므로 PURPOSE 예외는 "확장 껍데기만" 으로 좁게 열 수 있다 (O8). 스탠드얼론이 필요해지면 pywebview(Python)로 PURPOSE 안에서 낸다.

| 위험 | 대응 (기본값) |
|---|---|
| **세션 간 프롬프트 주입** — 한 세션의 출력이 다른 세션의 지시가 된다 | 메시지는 데이터로 전하고 출처를 붙인다 · 권한 변경 · 되돌릴 수 없는 일 · 비밀 요청은 메시지만으로 하지 않는다 · 의심 메시지는 사람에게 |
| **원격 실행** — 세션 요청은 사실상 그 PC 에서 에이전트를 실행하는 일이다 | 중계가 허용 목록(프로젝트 · 디렉터리 · 하네스 · 권한 모드)을 갖고, 세션 요청은 사람 승인마다 (O4) · 중앙이 PC 로 들어오는 길 없음 (§2) |
| **폭주** — 오케스트레이터가 세션을 계속 띄우거나 배정을 돌린다 | PC 동시 세션 · 하루 턴 · 프로젝트 하루 세션 요청 상한 · 중계 정지 스위치 · 상한에 닿으면 사람에게 |
| **오케스트레이터 단일 장애** | lease 만료 → 허브가 풀고 사람에게 · 작업 세션은 받은 배정을 계속한다 |
| **비용 · 계정** — 비대화형 세션은 사용자 계정 · 요금으로 돈다 | 세션 요청에 하네스 · 계정 표시 · 상한을 사람이 정한다 |
| **네트워크 노출** | 중계 화면은 loopback 기본 · 중앙으로는 나가는 연결만 · 토큰은 지금 규칙(R0.5 — 기록에 싣지 않음) |
| **조용한 실패** — 전달 안 된 메시지 · 죽은 세션을 살아 있다고 본다 | 상태 `unknown` 을 따로 세고 화면에 숫자로 · 마지막 신호 시각 표시 |

## 8. 부딪치는 기존 결정

| 기존 결정 | 내용 | 이 축의 제안 |
|---|---|---|
| 2.0 **D5** · 요구 **R15.3** | A2A · 유휴 점검은 첫 판에서 뺀다 · 허브는 하네스에 메시지를 보내지 않는다 | "첫 판" 조건은 2.0.0 발행으로 끝났다 — 이 축에서 **연다** (O1) |
| `multi_workspace_orchestration.md` **§0.6** | 중앙은 하네스에 메시지를 보내지 않는다 — 지시는 워크스페이스에 놓인다 | 1.x 흐름의 원칙으로 남기고, 2.0 허브에서는 **받은편지함(끌어오기)이 기본**, 밀어 넣기는 중계가 띄운 세션(T2)만 — "보낸다"가 아니라 "놓고 알린다"에 가깝게 |
| 2.0 **H4** · **R0.4** | 작업 환경은 kit 을 깔지 않는다 | 참여 조건으로 유지 · 중계는 선택 계층 (§5.2, O3) |
| **PURPOSE 제외 영역** | non-Python runtime (TypeScript …) | VS Code 확장 껍데기만 예외로 열지 (O8) |
| 2.0 **R15.4** · M-039 | arcturus 이전은 2.0 뒤 | arcturus 의 A2A 실험(docs/42 §8)은 이 축의 참고 자료 — 이전 일정과 묶지 않는다 |

| O2 | 세션을 허브의 새 단위로 두는가, 콜사인과의 관계는 | 세션 = 배정 · 전달 · 상태 단위, 작업 기억은 콜사인 단위 그대로 |

## 10. 단계 (안 — SDLC 순서, ADR-027)

| 마일스톤 | 단계 | 내용 |
|---|---|---|
| M-041 | concept | 이 문서 · 열린 결정 O1~O10 |
| M-042 | requirements | 요구 · **실측 S**: 하네스별 T1 hook · T2 비대화형 · 이어 가기 · 상태 읽기 (Claude Code · Codex, Linux 먼저) |
| M-043 | design | 스펙 (`hub_spec.md` 확장 또는 새 `hub_orchestration_spec.md`) · ADR |
| M-044 | implementation 1 | 세션 등록 · 상태 · 받은편지함 (T1 — 중계 없이) |
| M-045 | implementation 2 | 오케스트레이터 lease · 배정 · 메시지 · 보고 |
| M-046 | implementation 3 | PC 중계 허브 — 감독 · T2 · T3 알림 · 로컬 웹 |
| M-047 | implementation 4 | VS Code 확장 (O8 에 따라) |
| M-048 | stabilization · release | 하네스 · OS 실측 → 2.1.0 |

첫 쓸모는 M-044 · M-045 만으로 나온다 — 중계 없이도 오케스트레이터 세션이 배정하고 작업 세션이 다음 턴에 받아 간다.
중계(M-046)는 "쉬는 세션 깨우기"와 "새 세션 띄우기"를 더한다.
