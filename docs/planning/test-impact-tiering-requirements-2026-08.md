## R0. 불변 조건 (요구사항이 아니라 전제)

- **push 게이트 전량 2축은 축소하지 않는다.** CI 도 계속 2축 전량이다.
  본 축의 어떤 산출물도 게이트 경로의 검사 개수를 줄이는 코드를 넣지 않는다
  (concept §5 ⛔, TASK-2026-08-14-main-004 기각 재확인).
- 선택 실행의 기존 안전 계약(main-003)은 유지·강화만 한다: 미선언=항상 실행 /
  자기 파일 변경 시 무조건 실행 / 건너뛴 것 전부 출력 / "게이트가 아니다" 표기.

## R1. 검사 분류 계약 — 미선언과 의도적 전역을 구분한다

현재 `WATCHES` 부재는 "일부러 전역"(`check_no_repo_write`)과 "아직 분류
안 됨"(나머지 265개)을 **구분하지 못한다**. 보급의 완료를 말하려면 이 구분이
필요하다.

- **R1.1** 모든 검사는 셋 중 하나를 파일 안에 선언한다 (손 목록 금지 — 54차
  규칙 "손으로 유지하는 버킷은 새 분류를 조용히 삼킨다"):
  - `WATCHES = (<glob>, ...)` — 국소: 선언한 입력 표면만 관찰
  - 전역 선언 (예: `WATCHES_ALL_REASON = "<왜 diff 로 좁혀지지 않는가>"`) —
    의도적 전역: 항상 실행하되 **근거가 파일에 남는다**
  - 아무것도 없음 — **미분류**: 항상 실행 (기존 보수적 기본값 유지)
- **R1.2** 미분류 개수는 관찰 지표다: runner 또는 검사 하나가 미분류 목록을
  셀 수 있어야 하고, 보급 작업의 진척은 이 수의 감소로 잰다. **0 이 되는
  것을 강제하지 않는다** — 새 검사가 미분류로 태어나는 것은 허용하되, 낡은
  미분류가 쌓이면 관찰 축(M-007/WBS-7.3)이 신호를 낸다.
- **R1.3** 전역 선언의 표기와 이름은 design 단계가 정한다. 요구사항은
  "의도와 근거가 파일 안에 남고 기계가 셀 수 있다" 까지다.

## R2. 보급 판정 기준 — 무엇에 `WATCHES` 를 다는가

- **R2.1** 선언 대상 판정: 검사의 입력 표면이 **저장소 상대 glob 로 열거
  가능하고 안정적**일 때만 단다. 표면에 들어가는 것: 검사가 읽는 저장소
  경로 + 검사가 import 하는 kit 모듈 경로 + 검사 자신이 참조하는 설정 파일.
  자기 fixture 만 만들어 쓰는 검사는 "import 하는 kit 모듈 + 자기 파일" 이
  곧 표면이다.
- **R2.2** 선언은 **넓게 틀리는 쪽으로** 적는다 (`fnmatch` 의 `*` 가 `/` 를
  먹는 것은 이 방향의 오차라 안전 — main-003 계약). 좁게 틀리는 것이 유일한
  실패 모드이고, 그것을 R3 메타 검증이 잡는다.
- **R2.3** 보급 순서는 이득 순이 아니라 **위험 역순**이다: 입력 표면이
  자명한 것(fixture-only 단위 검사)부터. 표면 판정이 조금이라도 애매하면
  미분류로 남긴다 — 미분류는 안전하다.

## R3. 선언 메타 검증 — 좁은 선언을 잡는다

- **R3.1** 목적 단일: **좁은 선언**(실제로 읽는 경로가 선언 밖 → 그 검사가
  조용히 skip 될 수 있음)을 red 로 잡는다. **넓은 선언**(선언했지만 안 읽는
  경로)은 성능 잡음일 뿐이므로 최대 warn — red 로 하지 않는다.
- **R3.2** 채취 방식은 design 결정 사항이되, 요구 성질은: 검사 실행 중
  **저장소 안 파일 접근의 실측**이어야 한다 (정적 추정 금지 — 추측은 조용히
  틀린다, 54차 규칙). 후보: Python audit hook / `open` 계측 / OS 레벨 트레이스.
- **R3.3** 비용 상한: 메타 검증은 게이트 벽시계를 유의미하게 늘리지 않아야
  한다. 상시 전수(매 게이트 274개 전부 트레이스)가 이 상한을 넘으면 표본
  순환(회당 일부 검사)으로 낮추는 것을 허용한다 — 단 순환 주기 안에 전
  선언 검사가 한 번씩은 재져야 한다.
- **R3.4** 메타 검증 자신도 검사다: `REQUIRES_QUIET_REPO` / `CHECK_TIMEOUT_S`
  규약을 따르고, 되주입(일부러 좁은 선언을 심어 red 확인)으로 실증한다.
- **R3.5** 판정 결과에는 **무엇을 근거로 좁다고 봤는지**(접근 경로 vs 선언
  glob 의 차집합)가 실린다 — "불일치" 라고만 말하는 진단은 금지 (55차 규칙).

## R4. 커밋 전 단계 계약 — 사람의 선택을 선언이 대체한다

- **R4.1** CLAUDE.md 의 커밋 전 단계("관련 검사 + self_application")를
  `--changed` 기반으로 갱신한다: 사람이 "관련" 을 고르는 대신 선언이 고른다.
  편집 중 `--filter`(초 단위)와 push 게이트(전량 2축)는 그대로다.
- **R4.2** 전환 조건: R3 메타 검증이 gate 에 들어와 있고, 되주입 실증이
  끝난 뒤에만 CLAUDE.md 를 바꾼다 — 검증 없는 선언에 사람의 선택을 넘기지
  않는다.
- **R4.3** `--changed` 출력의 "게이트가 아니다" 표기는 커밋 전 단계로
  승격된 뒤에도 유지한다.

## R5. 이득 근거 실측 (2026-08-28, 이 호스트)

- memory/doc-only 변경에서 현재 선언 8개 상태의 `--changed`: **268개 실행,
  6개 skip, 105.76s** vs 같은 시점 1축 전량 **112~117s** — **절감 ~10s(~8%)**.
  무거운 검사를 걸러도 벽시계가 거의 안 주는 이유는 병렬 잔여 검사와 정숙
  직렬 구간(61s 실측, 2026-08-14)이 남기 때문이다.
- 따라서 **벽시계는 이 축의 1차 이득이 아니다.** 보급을 아무리 늘려도
  커밋 전 단계의 하한은 정숙 구간 ~60s 이고, 현실적 상한은 40~50% 절감이다.
- **1차 이득은 선택의 정확성이다**: 사람이 고르는 "관련 검사" 는 이 세션에서도
  두 번 틀렸다 — 생성물 정합 검사 2종(state/roadmap_state)은 memory 편집의
  "관련" 으로 사람이 고르지 않았지만 `--changed`(미선언=실행)가 잡았다. 그
  red 는 push 게이트까지 갔다면 게이트 1사이클(~4분 + 재실행)을 물렸을 것이다.
- 이 실측은 R2.3(위험 역순 보급)과 R4(사람 선택의 대체)의 근거이며, "보급
  확대 = 시간 절감" 프레임의 기각 근거다.

## R6. kit 이행 범위 — 이 저장소 밖으로

- `WATCHES` idiom · R1 분류 계약 · 3단 계층(편집=선택 / 커밋 전=선언 선택 /
  게이트=전량)은 **kit 표준 문서**(core)로 옮긴다 — 소비 프로젝트는 검사
  구성이 달라 이득 산수가 다르지만(전역 관찰 검사가 적으면 상한이 올라간다),
  계약 자체는 동일하게 성립한다.
- 문서 위치와 범위(runner 코드의 kit 노출 여부 포함)는 design 결정 사항.

## sign-off 기록 (2026-08-28, 소유자)

R1~R6 승인. 미결로 표기했던 3곳은 **권고안대로** 확정:

- **R1.3** 전역 선언 표기 = 파일 내 `WATCHES_ALL_REASON = "<근거>"` 방식
  (기존 `REQUIRES_QUIET_REPO` / `CHECK_TIMEOUT_S` 와 같은 파일 내 선언 idiom).
  정확한 이름 리터럴은 design ADR 이 최종 확정하되, "근거 문자열이 필수인
  파일 내 선언" 이라는 형태는 여기서 고정.
- **R3.3** 비용 상한 방식 = **상시 전수 우선, 실측이 상한을 넘으면 표본
  순환으로 강등** (순환 주기 안에 전 선언 검사가 한 번씩 재지는 조건 유지).
  전수/순환의 판정 기준 수치는 design 이 실측으로 정한다.
- **R4.2** 커밋 전 단계 전환 조건 = **메타 검증의 게이트 편입 + 되주입 실증
  이후에만** CLAUDE.md 갱신. 그 전에는 `--changed` 는 보조 수단으로만 쓴다.
