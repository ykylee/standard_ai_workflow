# 검사 입력 표면 선언 + 계층별 회귀 실행 계약 — concept 검토

- 대상 독자: 소유자 (M-008 다음 단계 결정), maintainer, workflow 설계자

## 0. 한 줄 결론 (draft)

> **"영향 부분만 점진 실행" 은 이 저장소에 이미 절반 구현돼 있다** (`--changed` +
> `WATCHES` 선언, 2026-08-14 main-003). 남은 절반은 (a) 선언 보급률을 8/274 에서
> 올리는 것과 (b) 그것으로 **게이트까지** 좁힐 수 있는가인데, (b)의 건전성 조건은
> 여전히 성립하지 않으며 이득 상한도 push 당 ~106s 로 작다. **권고: 게이트는
> 전량 유지, 투자는 편집 루프의 선언 보급(§5 B안)에 한정** — 단 그마저 이득이
> 실측으로 정당화될 때만.

## 1. 현재 실행 계층의 실태 (2026-08-28 실측)

이 저장소는 이미 3단 계층을 운용한다 (CLAUDE.md 게이트 절, 2026-08-14 소유자 승인):

| 계층 | 수단 | 선택 방식 |
|---|---|---|
| 편집 중 | `--filter=<이름조각>` | 사람이 고른다 (이름 기반) |
| 편집 중 (선언 기반) | `--changed` | **검사가 선언한 `WATCHES` glob ∩ git 변경 경로** |
| 커밋 전 | 관련 검사 + `check_self_application` | 사람이 고른다 |
| push 직전 (게이트) | 전량 2축 (`--branch-context=all`) | 선택 없음 |

`--changed` (main-003, 2026-08-14) 의 계약은 전부 "조용히 안 도는 검사" 를 막는
쪽으로 설계돼 있다: **미선언 = 항상 실행** / 자기 파일 변경 시 무조건 실행 /
parse 실패도 실행 / 건너뛴 것은 이름·사유 전부 출력 / 변경 0건이면 "통과" 가
아니라 "잴 것이 없음" / 매 출력에 **"이 실행은 게이트가 아니다"** 를 찍는다.

**선언 보급률: 274개 중 8개** (`check_branch_context_matrix` ·
`check_handoff_next_steps` · `check_mypy_config_actually_loaded` ·
`check_release_pipeline_lib` · `check_release_status_auto_bump` ·
`check_release_status` · `check_release_summary` · `check_wiki_score`).
이것은 미달이 아니라 **설계다** — 벽시계를 정하는 무거운 8개 중 7개에만 선언했다
(`check_no_repo_write` 는 관찰 범위가 사실상 저장소 전체라 **일부러 미선언**).
1초 미만 검사 160개에 선언을 다는 것은 벽시계를 거의 줄이지 않는다.

## 2. 건전성 조건 — 게이트를 좁히려면 무엇이 성립해야 하나

선택 실행이 **게이트** 자격을 얻으려면 다음이 전부 성립해야 한다:

1. **선언의 완전성(soundness)**: 모든 검사의 `WATCHES` 가 실제 입력 표면의
   **상위집합**이어야 한다. 하나라도 좁게 선언되면 그 검사는 조용히 안 돌고,
   그것이 정확히 "로컬 green + CI red" (15연속 red, 실측 비용 10일) 의 모양이다.
2. **전역 관찰 검사의 부재 또는 전수 포함**: `REQUIRES_QUIET_REPO` 류 —
   저장소 전역 상태(생성물 정합, 문서 파리티, 쓰기 부재)를 관찰하는 검사는
   입력 표면이 diff 로 좁혀지지 않는다. 이 저장소 검사의 상당수가 이 부류다.
3. **선언 자체의 검증 수단**: "선언이 실제 입력과 맞는가" 를 재는 메타 검사가
   없으면, 선언은 낡는다 (54차 규칙: 손으로 유지하는 버킷은 새 분류를 조용히
   삼킨다). 되주입 방식의 검증(선언 밖 파일을 바꿔 red 가 나면 선언이 좁다)은
   검사당 비용이 크고, 전 검사에 상시로 걸 수 없다.
4. **push 구성의 다양성**: 이 저장소의 push 는 세션 종료 규율상 거의 항상
   memory 갱신을 싣고, memory 문서는 브랜치 컨텍스트로 모양이 갈리는 데이터다
   — main-004 실측: 하루 5 push 전부 memory 포함, **생략 가능 push 실질 0**.

조건 1·3 은 도구로 좁힐 수 있는 여지가 있으나(§5 C안), 조건 2·4 는 이 저장소의
**구조적 성질**이라 도구 투자로 바뀌지 않는다.

## 3. 기각 이력 대비 — 이 검토는 무엇이 다르고 무엇이 같은가

| | main-004 (2026-08-14 기각) | 본 검토 (M-008) |
|---|---|---|
| 대상 | 게이트의 조건부 1축 생략 | 계층 전반의 선택 실행 계약 |
| 선택 근거 | '민감 경로' **휴리스틱** | 검사 자신의 **선언** (`WATCHES` 패턴) |
| 재론 정당성 | — | main-004 Follow-up 이 명시한 재론 조건: *"검사 저작 규약이 브랜치 컨텍스트 접근을 선언식으로 강제하게 되면 그때 다시 잰다"* |

**같은 것**: 게이트 축소의 기대비용 비대칭. main-004 실측 — 절감 push 당
~106s vs 오판 1회 10일. 이 산수는 선언 기반이 돼도 §2 조건 1~4 가 전부
성립하기 전에는 바뀌지 않는다. 53차 규칙("전량 게이트는 필터로 대체되지
않는다" — red 2건이 필터를 전부 통과하고 게이트에서만 잡혔다)도 그대로 적용된다.

**다른 것**: main-004 는 휴리스틱 판정이라 건전성이 *원리적으로* 불가능했다.
선언 기반은 원리적으로는 가능하나, §2 의 성립 비용(전 검사 선언 + 메타 검증)이
이득 상한을 넘는다는 것이 본 검토의 판단이다.

## 4. 이득 상한 — 무엇을 아낄 수 있나

- **게이트(push 직전)**: 축당 ~102–115s × 2축. 벽시계의 지배 요인은 무거운
  8개와 정숙 구간(직렬 61s)이다. 선택 실행으로 정숙 구간은 줄지 않고
  (`no_repo_write` 는 선언 불가), 무거운 8개 중 릴리스 계열은 memory-only
  push 에서 이론상 skip 가능 — 그러나 §2 조건 4 (memory 가 브랜치 컨텍스트
  데이터) 때문에 slash 축 자체를 생략할 수 없어, **게이트 절감의 현실적
  상한은 push 당 1–2분 수준**이다. 오판 비용 실측 10일과의 비대칭 유지.
- **편집 루프**: 이미 `--filter` 로 초 단위다. `--changed` 의 이득은
  "무엇을 돌릴지 사람이 고르는 비용" 의 절감인데, 선언 8개 상태에서도 무거운
  검사 회피는 이미 작동한다. 보급률을 올려 얻는 추가 이득은 **커밋 전 단계**
  에서 "관련 검사" 를 사람이 아니라 선언이 고르게 되는 것 — 아낄 수 있는 것은
  시간이 아니라 **선택 실수**다.
- **CI**: 대상 아님. CI 는 계속 2축 전량이다 (main-004 완료 기준 3 — 로컬이
  CI 보다 약해지는 방향의 비대칭은 만들지 않는다).

## 5. 소유자 선택지

- **A안 — 현상 유지 + 본 검토 종결**: 계층 계약은 이미 옳게 서 있다
  (편집=선택, 게이트=전량). M-008 을 concept 에서 닫고, 재론 트리거를
  main-004 와 같은 형태로 남긴다 (예: 게이트 벽시계가 X분을 넘거나, 전역
  관찰 검사 비중이 유의미하게 줄면 다시 잰다). **비용 0.**
- **B안 — 편집 루프 한정 투자 (권고 후보)**: 게이트는 전량 유지. `WATCHES`
  보급을 "무거운 것" 기준에서 "**커밋 전 관련 검사를 선언이 고를 수 있는
  수준**" 까지 올리고, CLAUDE.md 커밋 전 단계를 `--changed` 기반으로
  갱신한다. 선행 조건: 보급 대상을 늘렸을 때 실제로 아껴지는 시간/실수의
  실측 1회. **비용 소, 게이트 리스크 0.**
- **C안 — 선언 메타 검증까지 (requirements 단계로 진행)**: B안 + "선언이
  실제 입력 표면과 맞는가" 의 메타 검사(예: 검사 실행 트레이스로 접근 파일
  집합을 채취해 선언과 대조)를 설계한다. 게이트 축소는 **여전히 목표가
  아니다** — 메타 검증은 선언의 낡음을 잡는 품질 수단이다. **비용 중.**
- ⛔ **게이트 축소는 선택지에 없다**: §2 조건 2·4 가 이 저장소의 구조적
  성질인 한, 어떤 선언 품질로도 push 게이트의 전량 2축을 대체하지 않는다.
  이것은 main-004 기각의 재확인이다.

## 6. kit 관점 — 이 저장소 밖의 소비자에게는

본 검토의 산수는 이 저장소 실측이다. kit 을 소비하는 다른 프로젝트는 검사
구성이 다르므로 (전역 관찰 검사가 적고 단위 검사가 많은 프로젝트라면 §2
조건 2 가 약해진다), **`WATCHES` idiom 과 3단 계층 계약을 표준 문서로
옮기는 것** 자체는 A/B/C 어느 안에서도 가치가 있다 — 단 그것은 M-008 의
다음 단계(requirements)에서 범위를 정한다.
