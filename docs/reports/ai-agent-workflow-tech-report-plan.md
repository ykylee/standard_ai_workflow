### 발표 덱과의 관계 (파생 방향)

덱과 보고서는 **같은 논지 척추**(인과 사슬)를 공유하되 양식이 요구하는 것이 다르다:

| | 발표 덱 | 기술보고서 |
|---|---|---|
| 전달 단위 | 슬라이드 헤드라인 + 구술 | 문단 논증 + 근거 인용 |
| 은유 | 액자 (매일 기억을 잃는 신입) | 서론의 도입 장치로 1회, 본문은 실명 |
| 사례 | 은유 번역 ("매뉴얼 네 부 복사") | 원본 실명 (task ID 정규식 4곳 복제 + 검사명) |
| 근거 | 발표자 노트에 숨김 | 본문 승격 + 정량 실측 표 |
| 결론 | CTA (지금 시작할 한 가지) | 한계·향후 과제 포함 논의 |

## 1. 보고서 제목(안)과 초록 방향

- 제목(안): **매일 기억을 잃는 협업자와 일하기 — AI 에이전트 협업 워크플로우의 설계 원리와 자기 적용 실증**
- 부제(안): 상태 외재화·단일 정본·실행되는 규칙, 그리고 그것을 스스로에게 적용한 4개월의 기록 (저장소 최초 커밋 2026-04-18 실측 — 기간을 명기할 때는 이 값에서 파생)
- 초록 방향 (5문장 내외): ① AI 코딩 에이전트는 세션 경계에서 컨텍스트를 잃는 협업자다 ② 이 성질은 재탐색 비용을 넘어 재현성 상실·기각된 결정의 부활·중복 작업·기록 진실성 문제를 낳는다 ③ 본 보고서는 이를 4대 누수(시간/도구/사람/품질)로 정식화하고 설계 원리 3층(상태 외재화 / 단일 정본 / 실행되는 규칙)을 제시한다 ④ 원리를 구현한 표준 AI 워크플로우 킷을 저장소 자신에게 적용해 실증했다 (smoke 249종, 원리↔검사 매핑, north-star 지표) ⑤ 사례 3건과 운영 중 발견된 한계를 함께 보고한다.

## 4. HTML 산출물 규격

- 경로: `docs/reports/ai-agent-workflow-tech-report.html`
- 단일 파일, 외부 의존 0 (폰트 시스템 스택, 스크립트 불필요 — 정적 문서)
- 레이아웃: 논문 단일단 (본문 최대폭 920px), 제목부 (제목/부제/소속/일자) + 초록 박스 + 목차 + 번호 장 + 표 번호 (표 1, 표 2…) + 참고문헌
- 인쇄 대응: `@media print` A4, 페이지 나눔 제어 (장 제목 앞 분리, 표 내부 분리 금지)
- 테마: 종이·잉크 무드 유지하되 덱(`saw-onboard`)과 구별되는 보고서 톤 — 본문 세리프, 코드·경로 모노스페이스
- 사내 보고서 헤더 (조직명·문서번호 자리)는 placeholder 로 두고 사용자가 채움

## 5. 검증 계획

- 문서 메타데이터: 본 계획 문서는 저장소 규약 (목적/범위/독자/상태/수정일/관련 문서) 준수 — `check_doc_metadata` 대상
- 링크: 계획 문서의 상대 링크 실재 — `check_doc_links` 계열
- HTML: 브라우저 렌더 확인 + 인쇄 미리보기 (A4) 확인
- 완료 기준 (TASK-2026-08-11-main-016): 계획 문서 + 보고서 HTML + 문서 검사 green
