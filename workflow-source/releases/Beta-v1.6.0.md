## 0. 릴리스 판정

이 사이클의 주제는 **"탐침은 잰 단위가 맞아야 한다"** 다. 네 결함 모두
'무엇을 재는가 / 어디서 소비되는가' 가 어긋난 자리에서 났다:

- **state.json 백슬래시** — `safe_relpath` 가 호스트 표기를 그대로 내보내
  POSIX 소비자가 경로를 단일 파일명으로 읽었다. 산출물 형식은 소비자 기준이다.
- **emit command `python3` 고정** — Windows PATH 에는 `python3` 이 없다.
  emit 은 소비되는 머신의 관례를 따라야 한다 (win32 는 `python`).
- **emit PYTHONPATH** — bootstrap *자신*의 출처를 재고 있었는데, env 가
  소비되는 자리는 target 프로젝트다.
- **전역 도구의 외부 체크아웃 해석** — 실행 인터프리터가 다른 체크아웃의
  workflow_kit 을 조용히 돌렸다. 이제 doctor 가 그 상태를 두 경로를 명시해
  보고한다.

체크인되는 산출물(플러그인 payload · 하네스 예시)은 **`platform="posix"` 고정**
이다 — payload 는 해시로 드리프트를 재므로 렌더 호스트마다 내용이 갈리면 그
비교가 무너진다. 따라서 Windows 에서 플러그인 채널을 쓰려면 `python3` 별칭이
여전히 필요하다 (`docs/INSTALLATION_AND_USAGE.md` §7.0.0 플랫폼 주의).

### fix(state) — `safe_relpath` POSIX 정규화 (`bcb05cfb`)

Windows 호스트에서 생성된 `state.json` 의 경로 값이 백슬래시 표기가 되던 것을
두 분기(상대/절대 폴백) 모두 `as_posix()` 로 정규화. cross-host federation
소비자가 같은 파일을 같은 경로로 읽는다.

### fix(mcp) — emit 해석기 플랫폼 분기 (`24b75e2a`, main-017)

- 신설 `workflow_kit/common/python_launcher.py` 가 정본: win32 → `python`,
  그 외 → `python3`. `mcp_server_command(bridge, bundle, *, platform=None)` 이
  이를 따른다 (기본 = 현재 호스트, 체크인 산출물은 `"posix"` 고정).
- `wk doctor` preflight 는 **bootstrap 채널만** launcher 를 플랫폼으로 해석한다.
  플러그인 채널의 `python3` 전제는 리터럴 유지 — payload 가 그 이름을 spawn 한다.
- 잔여: Windows 호스트 실측(bootstrap emit → spawn 왕복)은 다음 Windows 세션
  (TASK-2026-08-25-main-017 in_progress).

### fix(mcp) — emit PYTHONPATH 를 target 레이아웃에서 판정 (`24b75e2a`, main-018)

`<target_root>/workflow-source` 가 실재할 때만 `PYTHONPATH: workflow-source` 를
emit. 순수 신규 프로젝트는 PYTHONPATH 없이 emit 되고 서버는 spawn 인터프리터의
site-packages 에서 `workflow_kit` 을 해석한다.

### feat 성격 — doctor `kit_resolution` 판정 (`24b75e2a`, main-019)

environment 절에 실행 인터프리터의 `workflow_kit` 해석 출처 판정 신설:
`project_checkout` / `interpreter_site_packages` (by design, 라벨만) /
`foreign_path` (**finding** — 잰 인터프리터 · 해석 출처 · project root 세 경로
명시). 다른 체크아웃의 코드가 조용히 실행되던 사고(61차 실증)를 보고로 끌어낸다.
